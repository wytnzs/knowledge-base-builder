# 模块安装

> 主 skill 负责“建库”；模块负责“建完以后每天怎么用”。
> 不一次全装。先装四个核心，用起来再装另外三个。

## 一、模块清单

| 模块 | 管哪一层 | 什么时候装 | 默认 |
|---|---|---|---|
| `inbox-triage` | `00-Inbox` | 第一天，入口开始积压时 | 装 |
| `knowledge-card` | `03-Knowledge` | 第一次要沉淀判断时 | 装 |
| `project-ops` | `01-Projects` | 第一个项目开始时 | 装 |
| `kb-health` | 跨层 | 第一周结束时 | 装 |
| `data-warehouse` | 外部数据 | 有表格、PDF、系统导出要变成能查的库时 | 按需 |
| `area-review` | `02-Areas` | 第一次周/月复盘时 | 按需 |
| `theme-map` | `03-Knowledge` | 三张以上卡片指向同一个问题时 | 按需 |
| `me-update` | `05-Me` | 标准或身份要改时 | 按需 |

**默认四件套**：`inbox-triage` + `knowledge-card` + `project-ops` + `kb-health`。
**另外三个**等库跑起来再装——没用到就装，只会多三个不会触发的文件。

## 二、怎么装

1. 读 `modules/<模块>/SKILL.md`；
2. 把里面的占位符换成新库的实际路径：

| 占位符 | 换成 |
|---|---|
| `{{INBOX}}` | 入口目录，如 `00-Inbox` |
| `{{PROJECTS}}` | 项目目录，如 `01-Projects` |
| `{{AREAS}}` | 领域目录，如 `02-Areas` |
| `{{KNOWLEDGE}}` | 知识目录，如 `03-Knowledge` |
| `{{ARCHIVE}}` | 归档目录，如 `04-Archive` |
| `{{ME}}` | 我这一层，如 `05-Me` |
| `{{ROOT}}` | 库根目录 |
| `{{SKILL_ROOT}}` | 本 skill 的安装位置（体检脚本在它下面） |

3. 写到新库的 `.claude/skills/<模块名>/SKILL.md`；
4. 在新库 `README.md` 的“怎么用”里加一行：这个模块什么时候用。

**不要直接复制带占位符的文件**——占位符留在库里，等于没装。

## 三、串成一条管线

每个模块只管一个阶段，做完只建议下一步，由操作者决定要不要继续；完整工位图见 `协作路由.md`。

装完四件套，跑一遍最小管线：

```text
入口来一条材料
-> inbox-triage 分流
-> knowledge-card 铸成候选卡
-> project-ops 在项目里调用这张卡
-> area-review 复盘：这条判断对不对
-> 写回卡片或方向
```

跑通一次，才算真的装上。只装文件、没跑过，不算。

## 四、什么时候加模块

- 每周复盘开始做了 → 装 `area-review`；
- 卡片超过十张、开始问“我到底怎么判断” → 装 `theme-map`；
- 发现自己反复交代同一套标准 → 装 `me-update`；
- 有一批表格、PDF、系统导出要变成能查的库 → 装 `data-warehouse`。

## 四之一、外部数据结构化（data-warehouse）

它跟其他模块不一样：其他模块管的是“库里的东西怎么流转”，它管的是“外面的数据怎么压进来”。

装的时候多做三件事：

1. 先定一条记录是什么（一个判例 / 一个产品 / 一个客户 / 一份资料）；
2. 先问他怎么查，再定字段——字段由查法决定，不由数据里有什么决定；
3. 建 `{{DATA_ROOT}}/_schema/schema.json`，以后所有入库都先读它，结构变了升版本。

建库和导入用模块自带的脚本：

```text
python .claude/skills/data-warehouse/scripts/init_warehouse.py \
  --schema "数据/_schema/schema.json" --db "数据/data.db" \
  --csv records=原始数据.csv
```

原文不搬进库，只存路径；库里存压缩后的记录。先导 20 条样本，验收后再全量。

## 五、更新和卸载

- 模块改了，版本号加一，写清为什么改；
- 三个月没触发过的模块，卸载，别留着占入口；
- 卸载不删它产出的文件，只删 `.claude/skills/` 下的那份 skill。

## 六、先做角色映射（重要）

装之前先确认新库的六个角色分别对应哪个目录。名字不一样没关系，别硬套：

| 角色 | 默认目录 | 你的库叫什么 |
|---|---|---|
| 入口 | `00-Inbox` | |
| 项目 | `01-Projects` | |
| 领域 | `02-Areas` | |
| 知识 | `03-Knowledge` | |
| 归档 | `04-Archive` | |
| 我 | `05-Me` | |

- 没有对应层的模块先不装。比如没有领域，就先不装 `area-review`；
- 名字不一样，装的时候传实际目录名：

```text
python scripts/install_modules.py --target "D:/我的库" --modules default \
  --inbox "01-收件" --projects "02-项目" --areas "03-方向" \
  --knowledge "04-判断" --archive "09-归档" --me "00-我"
```

- 装完 grep 一遍 `{{`，有残留就是没装好。

## 七、脚本

```text
python scripts/install_modules.py --list
python scripts/install_modules.py --target "D:/我的库"                 # 默认四件套
python scripts/install_modules.py --target "D:/我的库" --modules area-review,theme-map
python scripts/install_modules.py --target "D:/我的库" --dry-run        # 只看不写
```

- 已存在的模块默认跳过，`--force` 才覆盖；
- 体检模块依赖主 skill 的 `scripts/check_kb.py`；主 skill 不在本机时，体检那一步改用人工五看；
- 模块装进去不是结束，按本库的写入规则微调两句，再跑一遍最小管线。
