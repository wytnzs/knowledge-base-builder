# 协作路由

> 主 skill 和八个模块是同一条流水线的不同工位，不是九个互斥的工具。
> **交接是建议，不是自动执行。** 每个 skill 做完，只问“现在有条件做下一步，要不要做？”操作者说做，才调用下一个。
> 基座怎么接、模块怎么登记、版本怎么升，见 `基座契约.md`；这一页只讲工位怎么流转。

## 一、工位图

| 阶段 | 用谁 | 输入 | 输出 | 下一步建议（等操作者确认） |
|---|---|---|---|---|
| 0.4 了解你（可选） | 本 skill | 工作区、已有 skill、微信（先问同意） | `现状扫描.md` + `工作-数据-技能表.md` | P1 定位 |
| 0 建库 / 重构 | `knowledge-base-builder` | 想建库的人 | 六区骨架 + 五个根文件 + 工作回路 + 采用计划 | 跑第一条回路 |
| 0.5 第一条回路 | 本 skill + 他的内容管线 | 一件真事 + 真材料 | 一个真产出 + `采用记录.md` 第一行 | `inbox-triage` / 装模块 |
| 0.6 采用诊断 | 本 skill | 建了但没用的库 | 一条回路 + 用真材料跑到跑通 + 断点 | 跑回路 |
| 1 收件 | `inbox-triage` | 入口积压 | 分流清单 + 候选卡 | `knowledge-card` / `project-ops` / `data-warehouse` / 归档 |
| 2 铸卡 | `knowledge-card` | 一条经验、案例、方法 | 候选卡 → 正式卡 | `theme-map` / `project-ops` |
| 3 主题 | `theme-map` | 多张卡指向同一问题 | 主题页 | `project-ops` / `knowledge-card` |
| 4 项目 | `project-ops` | 有终点的事 | 项目状态 + 收尾三问 | `knowledge-card` / `area-review` |
| 5 复盘 | `area-review` | 一个方向的周期 | 成长记录 + 上游修改 | `knowledge-card` / `me-update` / `project-ops` |
| 6 我这一层 | `me-update` | 标准、身份、偏好变化 | `05-Me` 的一处 diff | 回到当前阶段 |
| 7 外部数据 | `data-warehouse` | 表格、PDF、系统导出 | 结构化库 + schema | `knowledge-card` / `project-ops` |
| 8 体检 | `kb-health` | 整个库 | 体检报告 + 一项修复 | 任一阶段 |

## 二、五条协作规则

1. **不二选一，但不自动跳**：一个任务可以连用多个 skill，每步做完先问操作者要不要继续，得到明确同意才调用下一个。
2. **做完必给建议**：说清下一步可以做什么、带什么过去，然后停下等回复。
3. **不越界**：每个 skill 只写自己那层；判断卡的正文在 `03-Knowledge`，项目里链接；外部数据的记录在 `data-warehouse`，卡片里不重存。
4. **先收后炼**：入口没清完，不急着铸卡；项目没跑起来，不急着建主题页。
5. **体检随时插入**：任何阶段都可以先体检，但只修最堵的一项，修完回到原阶段。

## 三、冲突怎么判

| 他说的话 | 先走 | 再建议（等确认） |
|---|---|---|
| 知识库不好用 | `kb-health` 体检 | 结构性问题 → `knowledge-base-builder` |
| 这条材料放哪 | `inbox-triage` | 能提炼判断 → `knowledge-card` |
| 这个项目做完了 | `project-ops` 收尾 | 判断 → `knowledge-card`；周期复盘 → `area-review` |
| 外部数据里有个结论 | `data-warehouse` 存记录 | 判断 → `knowledge-card`，两边链接 |
| 标准改了 | `me-update` | 改完回到当前阶段，不影响别的 |
| 几张卡说的是同一件事 | `theme-map` | 缺证据 → `knowledge-card`；拿去做项目 → `project-ops` |

## 四、交接话术（照说）

> 这一步做完了：……。现在有条件做下一步「X」，要不要做？你不说做，我就停在这里。

- 只陈述条件和建议，不替操作者判断“该往下走了”；
- 操作者说“先不做”，就记进进度文件，不反复劝；
- 操作者说“做”，才调用下一个 skill。

## 五、一条最小管线

```text
入口一条材料
-> inbox-triage 分流
-> knowledge-card 铸成候选卡
-> project-ops 在项目里调用
-> area-review 复盘这条判断对不对
-> 写回卡片或方向
```

跑通一次，才算模块真的装上。只装文件、没跑过，不算。

## 六、别做的事

- 不要在 `knowledge-card` 里顺手改项目状态；
- 不要在 `project-ops` 里复制一张卡；
- 不要在 `data-warehouse` 里写判断；
- 不要在 `kb-health` 里全面翻修；
- 不要让主 skill 接日常活；
- **不要自动调用下一个 skill**；
- **不要替操作者判断该不该往下走**。
