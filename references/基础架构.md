# 基础架构

> 六个角色，按 `00–05` 排。名字可以换，角色不变。
> 这一版来自 2026-11-06 的重构：**领域管长期，项目管短期**；知识单独一层；“我”单独一层。

## 一、六个角色

| 区 | 回答什么问题 | 必有 / 按需 |
|---|---|---|
| `00-Inbox` 入口 | 新东西先放哪 | 必有 |
| `01-Projects` 项目 | 眼下有交付、有做完那天的事，到哪一步 | 必有 |
| `02-Areas` 领域 | 长期要做什么、守住什么标准、怎么算有效 | 有长期方向就建 |
| `03-Knowledge` 知识 | 哪些是可复用的判断、方法和主题 | 必有 |
| `04-Archive` 归档 | 结束的、不用的放哪 | 必有 |
| `05-Me` 我 | 我是谁、我的标准、我的偏好和节奏 | 必有 |

按需再加：`客户/私密`、`成品/交付物`、独立数据仓。

> **领域和项目是两样东西，不放在一起。** 项目有终点，领域没有。项目平铺，用 `domain` 挂领域。

## 二、第一版（一场对话交付）

```text
我的知识库/
├── 00-Inbox/             新东西先丢这里，进来不分
├── 01-Projects/          正在做的事，平铺；一个项目一份 项目.md
├── 02-Areas/             长期方向（只有一个方向就建一个）
├── 03-Knowledge/         自己的判断、方法、主题；唯一正文
├── 04-Archive/           结束的、不用的
├── 05-Me/                我是谁、我的标准、偏好、节奏
├── README.md
├── 任务书.md
├── 分区职责表.md
├── 写入规则.md
├── 建库进度.md
└── 30天计划.md
```

第一版可以少建：没有长期方向就先不建 `02-Areas`；没有客户就不建客户区；成品先并进项目。
**但 00 / 01 / 03 / 05 / 04 这五个不能省。**

## 三、长全之后

```text
我的知识库/
├── 00-Inbox/
├── 01-Projects/
│   └── <项目名>/
│       └── 项目.md        domain / 状态 / 进度 / 卡点 / 下一步
├── 02-Areas/
│   └── <方向名>/
│       ├── 方向.md        做什么、不做什么、标准、怎么算有效、下一步
│       ├── 记录规范.md    记什么、从哪取数、复盘问什么
│       ├── 攒下.md        这个方向的资产视图
│       └── 成长.md        每次复盘一条：原来 / 现在 / 依据 / 影响
├── 03-Knowledge/
│   ├── 知识卡片/          可复用的判断，唯一正文
│   ├── 主题/              多个问题指向同一处时才建
│   ├── 方法/              方法资产
│   └── _候选/             未签署的判断先放这
├── 04-Archive/
├── 05-Me/
│   ├── 我是谁.md          身份、立场、标准（AI 开工先读）
│   ├── 我的偏好与边界.md
│   └── 周节奏.md
└── README.md
```

## 四、项目与领域怎么连

- 项目平铺在 `01-Projects/`，**不放进领域目录**；
- `项目.md` 里写 `domain: 理赔`，一个项目挂一个主领域；跨领域的写 `_跨领域`；
- 领域页只写方向、标准、记录规范、攒下、成长；项目由视图按 `domain` 自动列出来；
- 好处：项目可以换领域、可以跨领域，不用搬家；领域一直很薄。

**判断句**：这件事有做完的那天吗？有 → 项目；没有 → 领域。

## 五、为什么把“我”单独一层

- AI 每次开工先读 `05-Me/`，一份说明书，不是简历；
- 里面只装会影响判断和交付的东西：身份、立场、标准（写作口吻、审美、配图、脱敏、底线）、偏好、节奏；
- 项目记录、业务知识不许进这一层——它会持续改，混进业务就没人维护了。

## 六、什么固定，什么可变

**固定（换了就不叫这个库了）**：

1. 入口唯一，进来不分类；
2. **领域管长期，项目管短期**，两样分开；
3. 判断只有一份正文，放在知识层；
4. 来源只读，不进判断层；
5. `05-Me` 是 AI 的说明书，开工先读；
6. 结束的进归档，不搬走、不删除；
7. 每个区能说清“放什么 / 不放什么 / 谁来写”。

**可变（必须由他的工作决定）**：

- 区叫什么名、几号开头；
- 有没有 `02-Areas`（只有一个方向就先写一个文件）；
- 客户、成品要不要单独成区；
- 来源要不要拆成独立仓；
- 顶层 5–8 个都可以。

## 七、什么时候拆成独立仓

四条满足两条才拆：

1. 数量大（上千份）；
2. 格式杂（PDF、图片、录音）；
3. 私密性强（客户、案件）；
4. 需要单独备份或单独给人看。

拆了以后**只读调用**，不往仓库里写判断。

## 八、一份东西放哪

从上往下问，第一个“是”就停：

1. 它帮哪个**正在做的事**？→ `01-Projects`
2. 它服务哪个**长期方向**（方向、标准、复盘）？→ `02-Areas`
3. 它是**可复用的判断/方法/主题**？→ `03-Knowledge`
4. 它是**别人的材料**？→ 来源区或独立数据仓
5. 都不是 → `04-Archive`

**注意**：项目里用到的判断，正文在 `03-Knowledge`，项目里链接过去，不复制一份。

## 九、命名

- 数字前缀只管顺序：`00-Inbox`、`01-Projects`、`02-Areas`、`03-Knowledge`、`04-Archive`、`05-Me`；
- 名字用他的话，不用术语：他说“案子”就别写“项目”；
- 不出现“其他 / 杂项 / 待分类 / 临时”；
- 顶层不超过 8 个。
