# 工作回路

> 库建得再整齐，没接进一件真事，就等于没建。
> 回路是「用上」的最小单位：一件他反复做的事，从库里取，做完写回去。

## 一、什么叫用上

不是「他打开过库」，也不是「库里有卡片」，而是：

- 同一件事，第二遍做的时候，他先来库里取；
- 取完能少说几句话、少翻几个文件；
- 做完有东西写回去，库里因此变厚。

一条回路跑通，比建十个目录有用。

## 二、回路卡（一条一张）

```text
回路名：        （用他的话，如「周三发公众号」「见客户前准备」）
多久一次：      （每周三 / 每次见客户 / 每接一个案子 / 每月底）
触发：          （什么信号出现时开始）
读什么：        （按顺序：05-Me → 方向 → 卡片 → 素材/客户/项目）
产出什么：      （一个具体交付物：选题、初稿、话术、方案、复盘）
写回什么：      （做完往库里写：新卡片、项目进度、客户记录、成长）
谁来做：        （哪个模块 / 哪个内容管线 / 人工）
算用上：        （按这件事本身的频率跑；产出有没有被真用）
```

## 三、建库当天跑第一条

四轮建库之后，不要停在「架子搭好了」。当场挑一条回路，用他的真材料跑一遍：

1. 让他选一件最近真会发生的事；
2. 按回路卡走一遍：读 → 做 → 写回；
3. 产出必须是他能直接拿去用的东西（不是演示）；
4. 把这次记进 `采用记录.md`，标「第一次」；
5. 问他一句：「下次同样的事，你第一步会做什么？」答得出来，才算看见。

跑不通就说明结构有问题，回 P2 改，不往后装模块。

## 四、按回路选模块

不按「默认五件套」硬装，先看他的回路：

| 回路 | 先装 | 第一条管线 |
|---|---|---|
| 写内容（公众号 / 小红书 / 口播） | 收件、铸卡、项目、复盘 + 内容管线 | 选题 → 素材 → 成稿 → 回写 |
| 见客户 / 销售 | 收件、铸卡、项目 + 客户库 | 见前调档 → 见后回写 |
| 接案子 / 理赔 | 收件、铸卡、项目 + 判例库 | 接案 → 查类案 → 方案 → 回写 |
| 做汇报 / 职场 | 收件、项目、复盘 | 周报 → 项目状态 → 复盘 |
| 学习 / 研究 | 收件、铸卡、主题 | 输入 → 卡片 → 主题 → 输出 |

刚起步只装跑这条回路需要的；其余的等第二条回路出现再装。

## 五、准备真材料，跑到跑通为止

不按天数验证。按“这一件真事有没有跑完”算：

1. 建库当天，或下一次这件事真发生的时候，准备真实材料；
2. 按回路卡走：读 → 补料 → 产出 → 写回 → 记 `采用记录.md`；
3. 跑完算一次，不设“几天内必须跑几次”；
4. 产出他真能用，才算跑通；跑不通就回 P2 改结构，或换一条回路；
5. 下一次同一件事发生，再跑一次。用着用着就固定了。

**一天能跑完，就不要拖到以后。** 能当天做的事，不排进“以后再说”。

没跑起来，不怪他懒，先查断点：

| 现象 | 断在哪 | 改哪 |
|---|---|---|
| 想不起来用 | 触发没写清 | 回路卡的「触发」 |
| 打开了不知道读什么 | 入口 / 调用表不清 | 写入规则或 Agent 规则 |
| 读了但产不出 | 库里缺判断 / 素材 | 补卡片或来源 |
| 产出了但没写回 | 写回动作太重 | 把写回压到一行 |
| 跑过一次就不再用 | 回路不是真需求 | 换一条回路，不硬撑 |

## 六、持续用，持续改

- 每次真事发生就跑，不按周打卡；
- 每跑 3 次，看一次断点：哪一步最费劲、哪一步被跳过、库里的东西有没有被真用上；
- 每次只改最堵的一处，改上游：回路卡、`AGENTS.md`、写入规则、模块，不是改这一次的产出；
- 第一条稳定后再加第二条。判断标准不是“跑了几天”，是“跑了几次、每次能不能在 30 分钟内完成”；
- skill 本身也按这个走：同一处卡了 3 次以上再改 skill，不凭一次体验改；改完升版本，写清为什么。

## 七、什么时候加第二条回路

第一条连续跑 3 次、每次不超过 30 分钟，再加第二条。一次上三条，通常一条都活不下来。

## 八、跑一条回路的固定动作

用户说「开始跑周三发公众号」时，按这六步：

1. **读**：读回路卡和卡上写的文件；用一句话告诉他，这次读到了什么、缺什么；
2. **补料**：缺判断回 `03-Knowledge` 找卡或铸卡，缺素材去来源区找；找不到就如实说“缺 X”，不硬编；
3. **产出**：按回路卡的“产出什么”做；如果是内容生产，接对应的内容管线 skill；
4. **写回**：至少写一样，写在他指定的地方；
5. **记录**：在 `采用记录.md` 记一行——日期、回路、读了什么、产出、写回、用没用上、最费劲的一步；
6. **收尾**：问一句“下一次什么时候跑？”，然后停。

**不许跳过第 1 步直接产出。** 不先读库，产出就是通用答案，等于没用库。

## 九、不要做的事

- 不要替他编一个「应该有用」的回路；
- 不要把「整理库」当回路——那是维护，不是工作；
- 不要在第一条回路没跑通时装一堆模块；
- 不要用「他知道了」代替「他跑过了」。
