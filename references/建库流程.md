# 建库流程

> 每阶段只有四件事：**为什么做、怎么做、交出什么、过什么门**。门不过，不往下走。

## 一次对话交付什么（最小路径）

四轮，一场对话。目标不是“方案”，是“能用的第一版”。

```text
第 1 轮  P1 定位        → 任务书
第 2 轮  P2 分区        → 职责表 + 他点头的区当场建出来
第 3 轮  P3 入口与写入  → 入口能用 + 写入规则
第 4 轮  P9 交钥匙      → README + 进度 + 30 天计划
```

第一版只要求三件事：**放得进一份真材料、找得回来、产出一个他真拿去用的东西。**
资产、项目、复盘、管线不在第一天建，等他用到再长。

**边用边改**：每用一轮，只改最堵的那一处，不全面翻修。改之前先看 `建库进度.md` 记的“下次从哪开始”。

---

## P0 接待

**目的**：判断这次是建、长还是修；让他知道这次能得到什么、你不会动他什么。

**动作**：
1. 只看不改：扫一眼他现有的文件夹，知道大概有什么；
2. 问清这次想解决的那一件事；
3. 说一句约定：“这次我们只做 X，你的原文件我不动。”

**产出**：一句话约定，写进 `建库进度.md`。

**门**：他能复述这次要做什么、不做什么。

**坑**：一上来讲方法论、给目录树、展示你的库。

---

## P1 定位

**目的**：把“我想建个知识库”变成一个具体的输出。

**动作**：
1. 按 `访谈问题库.md` 的 P1 四问走；
2. 起草任务书，五栏填满；
3. 填不满的栏目标“待定”，不要编。

**产出**：`任务书.md`

```text
为谁：
在什么场景：
用什么知识：
产出什么：
怎么算有用：
```

**门**：
- 能说出 30 天内会发生的一个真实输出；
- 如果他的场景在 30 天外（比如三个月后开学），追问“最近一次同样的事是什么时候”，用最近一次定第一版；
- 手上有至少 3 份真实材料；
- “怎么算有用”能落到可观察的结果，不是“提升效率”。

**坑**：把愿望当输出；替他想一个“应该有用”的场景。

---

## P2 分区

**目的**：让每份东西都有唯一的地方，而且他能说清为什么。

**动作**：
1. 让他把材料按“谁写的、干什么用”粗分三堆：**我自己想的 / 别人给的 / 正在做的事**；
2. 从三堆推出最少的分区，通常 5–7 个（六个角色，按需减）：

| 角色 | 放什么 | 不放什么 |
|---|---|---|
| 00 入口 | 所有新东西，进来不分 | 已处理的、正式成果 |
| 01 项目 | 有交付、有做完那天的事；平铺，用 domain 挂领域 | 日常琐事、长期方向 |
| 02 领域 | 长期要做的事：方向、标准、记录规范、复盘 | 项目过程、具体卡片 |
| 03 知识 | 自己的判断、方法、主题；唯一正文 | 原文、书摘、聊天记录 |
| 05 我 | 我是谁、我的标准、偏好、节奏 | 项目记录、业务知识 |
| 04 归档 | 结束的、废弃的 | 还在用的 |
| 客户/私密 | 客户、案件、隐私材料 | 任何要公开的内容 |
| 成品/交付物 | 已经做出来、要反复用的东西：方案、一页纸、模板、成品稿 | 半成品、素材 |

3. 每份东西放哪，从上往下问，第一个“是”就停（行动导向的排序）：
   - 它帮哪个**正在做的事**？→ 01 项目
   - 没有的话，它服务哪个**长期方向**（方向/标准/复盘）？→ 02 领域
   - 没有的话，它是**可复用的判断/方法/主题**吗？→ 03 知识
   - 没有的话，它是**别人的材料**吗？→ 来源区或独立仓
   - 都不是，**归档**。
4. 数据量大、格式不同、私有性强、要单独备份的，才拆成独立仓；否则先不拆；
5. 每个区写三句：**放什么 / 不放什么 / 谁来写**；成品和交付物必须有家，要么放项目里，要么单独一区；
6. 方向少于两个时，写成一个 `方向.md`，不建目录；成品先并进项目，不单独成区；
7. 他点头的区，这一轮就在他电脑上建出来；没点头的不建，不留空目录。

**产出**：`分区职责表.md` + 已建出的区（只建他点头的）

**门**：
- 随手给三份真实材料，他能当场说出去哪、为什么；
- 没有“其他 / 杂项 / 待分类”；
- 顶层不超过 6–8 个。

**坑**：按学科分；一次建十个空目录；把“来源”当“资产”。

---

## P3 入口与写入

**目的**：让新东西有固定入口，让“处理完”有标准。

**动作**：
1. 定唯一入口（一个文件夹），规矩是**进来不分类**；
2. 定处理动作：每周一次，把入口里的东西分成五种去向——留作来源 / 提炼判断 / 进项目 / 归档 / 删（先列清单再删）；
3. 定“什么值得留”：只留有启发性、有实用性、跟他有关、够新的；不抓“以后可能有用”的整篇。抓的时候不分类；
4. 定写入规则：
   - 什么情况下建一张卡（能复用、能改变判断、能回答一个问题）；
   - 什么情况下**不**建卡（看完就完、没有自己的观点、重复）；
   - 最小字段：标题、类型、一句话说明、来源、日期；
   - 命名规则：能被自己半年后看懂。

**产出**：`写入规则.md`

**门**：拿三个真实场景走一遍——新收到一份资料、冒出一个想法、来了一条客户信息——每条都能说出去哪、怎么处理。

**坑**：规则写得太细，没人执行；把“整理”当“处理”，只搬不判断。

---

## P4 我这一层（05-Me）与调用

**目的**：让 AI 不用每次重新认识他。

**动作**：
1. 建 `05-Me/`：我是谁 / 我的标准 / 我的偏好与边界 / 周节奏。四份或合成一份都行；
2. “我的标准”写会影响交付的东西：写作口吻、审美、配图、脱敏、底线；
3. 写调用表：他最常问的三类问题，各自先查哪里；
4. 这一层只写会影响判断的事，不写简历、不放业务记录。

**产出**：`05-Me/`（至少 `我是谁.md`）+ 调用表（可合进 README）

**门**：新开一个会话，只读 `05-Me/`，AI 能说对他做什么、不做什么、按什么标准做。

**坑**：写成个人简历；写了没人读——身份文件必须在入口文档里被指到。

---

## P5 资产

**目的**：让原料变成能反复用的判断。

**动作**：
1. 从他“跟人讲过不止一次”的经验里挑一条，做第一张卡；
2. 卡片只写四样：**一句话判断 / 依据 / 适用边界 / 来源**；
3. 提炼按层走：原文留着 → 加粗关键句 → 用到时再压成一句自己的判断。抓的时候不提炼，用的时候才提炼；
4. 新判断先放候选区，他签了才进正式区；
5. 多个卡指向同一个问题时，才建主题页；主题页只综合，不复述卡片。

**产出**：第一张卡 + `资产规则`（可并入写入规则）

**门**：随机抽一张卡，能沿来源追到依据；他能说出这张卡什么时候用、什么时候不能用。

**坑**：把书摘做成“我的卡”；一上来建一百张；只有标题没有判断。

---

## P6 项目

**目的**：让正在做的事有状态，不靠脑子记。

**动作**：
1. 从“最近在做的三件事”里挑一件有截止的，建第一个项目；
2. 每个项目一份状态，五栏：

```text
领域 / 状态（进行中·已完成·暂停）/ 进度 / 卡点 / 下一步
```

3. 项目平铺在 `01-Projects/`，不放进领域目录；用 `domain` 挂领域，一个项目一个主领域；
4. 交付后留在原目录，不搬走，继续被调用；
5. 项目启动时写一句目标；完成时问三句：当时怎么处理的、目标达成没有、下次改什么（启动清单 / 收尾清单）；
6. 如果项目多到一个屏看不完，做一个自动汇总视图；没有工具就手工一周更新一次。

**产出**：第一个项目 + `项目规则`

**门**：他能在十秒内说出每个项目“下一步做什么”；工作台上看得见。

**坑**：把日常事务当项目；项目没有终点；交付后到处搬。

---

## P7 复盘与节奏

**目的**：让系统自己变好，而不是靠他自觉。

**动作**：
1. 每个方向写一份记录规范：**记什么 / 从哪取数 / 复盘问什么 / 什么算好**；
2. 领域里分两样：**标准**是底线，守住就行；**怎么算有效**是进展，看增长。复盘两样都看；
3. 复盘固定四栏：

```text
原来：我原来怎么判断
现在：现在怎么判断
依据：哪件事、哪条证据让我改了
影响：改了哪个文件（卡片/规则/项目/流程）
```

4. 节奏按他的真实时间定：每周小结清入口、每月小结看方向、每季度看结构；写到具体时间（周三晚上），不写“找时间”；
5. 写下“如果这周没做，下周补哪一步”，不写“要坚持”。

**产出**：`复盘规则.md` + `节奏.md`

**门**：完成一次真复盘，且 diff 里有一个上游文件变了——不是只改了稿子。

**坑**：复盘写成流水账；节奏定得比他的时间多。

---

## P8 管线

**目的**：把每周重复的活变成能重复跑的流程。

**动作**：
1. 先从 `modules/` 里挑现成的，不从头写；默认五件套和安装方法见 `references/模块安装.md`；
2. 找那件“每周都要做、步骤差不多、有判断标准”的事；
3. 拆成三段：**从哪取数 → 怎么做 → 交到哪**；
4. 写成一条流程（skill 或清单），写清：什么时候触发、几步、每步验收；
5. 接上数据：读哪个区、写回哪个区；写回必须落到文件。

**产出**：已装的模块 + 第一条管线

**门**：同一件事跑第二遍，他需要交代的话明显变少；不该触发的时候不触发。

**坑**：为做而做；流程里写死某个具体内容；只输出不回写。

---

## P9 交钥匙

**目的**：他离开这次对话也能用、能接着建。

**动作**：
1. 写 `README.md`：一句话说明这个库干什么、怎么用、每个区放什么、三条规矩；
2. 写 `建库进度.md`：走到哪、定了什么、待定项、下次从哪继续；
3. 写 30 天计划：

```text
第 1 周：往入口放 5 份真材料，处理一次
第 2 周：做第一张卡，用一次
第 3–4 周：开第一个项目，做一次复盘
```

4. 顺手写三行身份（我是谁 / 我在做什么 / 怎么跟我配合），让 AI 下次开工先读；
5. 可选：地图（现在有多少东西、哪里堵）和变更日志（结构变了才记）。

交付前对照第一版三条：能放进一份真材料、能找回来、能产出一个真用的东西。缺一条就说清楚缺哪条，不宣布建好。

在进度里写清：哪些区还是空的、第一周补哪三份材料。别把“架子建好了”说成“能用了”。

**产出**：`README.md` + `建库进度.md` + `30天计划.md` + `身份.md`（三行就够）

**门**：隔一周新开会话，只靠库里的文件能接着干。

**坑**：交付一堆文档没重点；README 写成说明书目录。

---

## 长大：库已经建过，但不好用

先体检，不急着改。五看：

1. **入口堵没堵**：入口里积压多久了？有没有第二个入口？
2. **家分没分清**：有没有两份一样的？有没有“其他”？
3. **资产长没长**：三个月新增了几张卡？有几张被用过？
4. **项目转没转**：有几个项目说不出下一步？
5. **复盘改没改**：最近三次复盘，改过上游文件吗？

按最堵的那一项补，不全面翻修。

## 重构：拆库、合库、换结构

顺序不能反：

1. **盘点**：列清单，标每个文件现在的家和新家；
2. **冻结**：迁移期间只读，不新增；
3. **建新**：先建新结构，不拆旧的；
4. **搬**：一次一个区，搬完验一次；
5. **留退路**：旧结构保留至少两周，确认没断链再归档；
6. **回滚**：任何一步出问题，退回上一步，不硬推。

存量超过一千份时，默认**不迁移**：旧库冻结只读，新库从今天开始，用到哪份搬哪份。
