# 项目推进

> 项目有做完的那天。没有终点的事，不是项目。

## 边界

- 项目平铺在 `{{PROJECTS}}/`，不放进领域目录；
- 一个项目一个主领域，写 `domain`；跨领域写 `_跨领域`；
- 项目里的判断，正文在 `{{KNOWLEDGE}}`，链接过去，不复制。

## 新建

先判断是不是项目：**有交付物、有做完的那天吗？** 没有 → 它是领域，不是项目。

`项目.md` 五栏：

```yaml
domain:
status: 进行中
progress:
blocker:
next_action:
```

## 更新（每次动项目时）

1. 只改三样：进度、卡点、下一步；
2. 下一步必须是一个动作，不是“继续推进”；
3. 卡住了，写清卡在谁、卡在哪一步。

## 收尾（项目完成时）

问三句，写进项目页末尾：

1. 当时是怎么处理的？
2. 目标达成没有？
3. 下次改什么？

然后把可复用的判断写进 `{{KNOWLEDGE}}/_候选/`，状态改「已完成」。项目目录不搬走。

## 产出

- 新建：一份 `项目.md`
- 更新：三栏变化
- 收尾：三问 + 至少一条候选判断

## 验收

- 十秒内能说出每个项目的下一步；
- 没有项目缺 `domain` 或 `next_action`；
- 收尾项目至少产出一条可复用判断。

## 下一步（只建议，不执行）

- 如果项目收尾产出了可复用判断，可以问操作者要不要用 `knowledge-card`；
- 如果这个方向到了复盘周期，可以问要不要用 `area-review`；
- 操作者不说做，就停在这里。

## 失败时

- 项目越开越多 → 先关掉三个说不出下一步的；
- 所有事都像项目 → 回到判断句：有做完的那天吗？
