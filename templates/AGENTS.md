# AI 协作规则（基座版）

> 这份文件是规则正文，给所有 Agent 看。开工前按「启动顺序」读，读完再动手。
> Claude Code 另有 `CLAUDE.md` 入口，Codex / WorkBuddy 直接读这份，通用聊天用 `AI协作规则.md`。

## 启动顺序

1. 读 `{{ME}}/我是谁.md`：他是谁、按什么标准交付、什么不做；
2. 读 `工作回路.md`：这次要做的是哪条回路、读什么、产出什么、写回什么；
3. 读 `写入规则.md`：东西从哪进、什么算处理完；
4. 读 `分区职责表.md`：每类东西放哪；
5. 只在跑脚本、装模块、升级时读 `.kb-base.json`。

**不许跳过 1 和 2 直接干。** 跳过 1 会写出不像他的东西；跳过 2 会做成一堆和本职工作无关的整理。

## 这个库为谁、干什么

- 他：{{为谁}}

每次开工会话，先按这三行对齐；和 `任务书.md` 不一致时，以 `任务书.md` 为准并提醒更新这里。

## 这个库的六个角色

| 角色 | 目录 | 放什么 |
|---|---|---|
| 入口 | `{{INBOX}}` | 所有新东西，进来不分 |
| 项目 | `{{PROJECTS}}` | 有交付、有做完那天的事；平铺，用 domain 挂领域 |
| 领域 | `{{AREAS}}` | 长期方向：方向、标准、记录规范、复盘 |
| 知识 | `{{KNOWLEDGE}}` | 自己的判断、方法、主题；唯一正文 |
| 归档 | `{{ARCHIVE}}` | 结束的、不用的 |
| 我 | `{{ME}}` | 我是谁、我的标准、偏好、节奏 |

**领域管长期，项目管短期，两样分开。** 项目不塞进领域目录。

## 五条硬规则

1. 一个东西只有一个家；别处要用，链接过去，不复制；
2. 判断的正文在 `{{KNOWLEDGE}}`，项目里只链接；
3. 别人的材料只进来源区或数据仓，不冒充他的判断；
4. AI 只提案，人签署；新判断先进候选区；
5. 删除、覆盖、迁移先列清单，等他确认；永不静默删。

## 路由

| 他要做什么 | 先读 / 先做什么 |
|---|---|
| 跑一条工作回路 | 读 `工作回路.md` 对应的回路卡，按「读 → 做 → 写回」走 |
| 处理入口 | `inbox-triage`：逐条给去向，原件不删 |
| 沉淀一条判断 | `knowledge-card`：四要素，先进候选区 |
| 推进项目 | `project-ops`：只改进度、卡点、下一步 |
| 周 / 月复盘 | `area-review`：四栏，至少改一个上游文件 |
| 体检 | `kb-health`：只修最堵的一项 |
| 改标准 / 身份 | `me-update`：先说明改什么、为什么 |
| 查外部数据 | 读数据仓 schema，只读，不写判断 |

路由里的模块名是默认五件套。**模块还没装时，按同样的步骤人工做，不报错、不硬等安装。**

## 交接

每个 skill 做完只建议下一步，问一句“现在有条件做 X，要不要做？”，操作者说做才调用下一个。
**不自动连跳，不替他判断该不该往下走。**

## 做完写回

任何一次回路做完，至少写回一样：

- 新判断 → `{{KNOWLEDGE}}/_候选/`
- 项目进展 → 项目 `项目.md`
- 客户 / 案件记录 → 对应库
- 判断变化 → 方向 `成长.md`
- 跑了几次 → `采用记录.md`

**只在对话里说“记下了”不算写回。**

## 禁止

- 不静默删除、覆盖、批量迁移；
- 不把书摘、课程笔记做成“他的卡”；
- 不替他判断“这个重要”；
- 不把个案结论写成普遍承诺；
- 不把判断写进数据仓。
