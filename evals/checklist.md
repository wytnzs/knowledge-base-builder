# 验收清单（五关）

> 验收对象是**这个 skill 本身**，不是被建的库。
> 每关都要留下证据：一段对话、一个文件、一次对比，不接受“我检查过了”。

## 第一关：进得来（触发）

- [ ] 20 句触发测试跑完，该触发 ≥18/20
- [ ] 10 句不该触发的，误触发 0
- [ ] description 里没有堆砌无关关键词

## 第二关：跟得下去（引导）

- [ ] 一个没建过库的人，前两轮不用作者解释
- [ ] 全程没出现“你说的是什么意思”
- [ ] 每轮只问 1–2 个问题
- [ ] 每轮结束他手里都有文件或决定
- [ ] 他说“我不知道”时有退路，不是卡死

## 第三关：长得出不同的库（适配）

- [ ] 三种不同职业各跑一遍（只是测试场景，不进交付物）
- [ ] 三套结构不同，且每套能解释“为什么这么分”
- [ ] 把职业换掉，结构跟着变
- [ ] 反证：三套跑出来一样 = 写死了，返工
- [ ] 测试用的职业没有预先给过结构；给了则本次结果作废

## 第四关：理念落在决策里（传承）

不看理念文档，只看它做的事：

- [ ] 没有把资料一股脑塞进一个目录（唯一入口 / 分库）
- [ ] 没有把书摘当用户自己的判断（来源决定归属）
- [ ] 没有一次建一堆空目录（最小起步）
- [ ] 没有跳过复盘直接收工（复盘写回）
- [ ] 没有替用户拍板（AI 提案、人签署）
- [ ] 没有删、覆盖或迁移用户存量
- [ ] 项目平铺在 `01-Projects`，用 `domain` 挂领域，没有塞进领域目录
- [ ] 判断的正文在 `03-Knowledge`，项目里是链接不是复制
- [ ] `05-Me` 里有“我的标准”，不只是身份介绍
- [ ] 领域的“标准”（底线）和“怎么算有效”（进展）分开写

## 第五关：交付得出去（运转）

- [ ] 建完关掉对话，隔一周新开会话能接着干
- [ ] 第一版跑 `python scripts/check_kb.py --root <库> --profile v0`，七项全过
- [ ] 状态文件、README、下一步都在
- [ ] 用 `scripts/install_modules.py` 至少装了默认四件套里的两个模块，并在新库里跑通一次“入口 → 卡片 → 项目 → 复盘”
- [ ] 模块里的占位符全部替换成本库实际路径，没有残留 `{{`
- [ ] 连续跑两个模块，交接不断（例如收件 → 铸卡 → 项目），没有互相踢皮球
- [ ] 不问作者也能继续
- [ ] 出现错误时，能追溯到是输入、规则、项目定义还是流程的问题
